# AGENTS.md

本守则适用于 Python 子项目。以行为契约为依据，在测试保护下演进，保持设计清晰并遵循 Python 惯用写法。

## 基本约束

- 每次变更围绕明确目标展开，避免混入无关重构。
- 公开接口提供完整的类型契约，不通过弱化类型或降低检查标准掩盖问题。
- 沿用项目已有工具与约定；新增第三方依赖须经明确批准。
- 保持公开行为兼容；必要的契约变更应明确说明，并同步文档。

## 测试驱动

- 新增行为和修复缺陷时，先用测试表达预期，确认测试因目标行为未满足而失败，再完成最小实现。
- 纯重构应保持可观察行为不变，并由已有测试保护；覆盖不足时先补充测试。
- 测试验证可观察的契约，避免依赖内部结构或重复实现逻辑。
- 测试应独立、可重复，外部条件可控；异步协作使用明确的同步信号，避免凭等待时长推断完成状态。
- 根据变更风险覆盖正常、失败、取消、并发和重复操作等相关路径。
- 类型契约同时验证合法用法被接受、非法用法被拒绝。

## 生命周期与异常

- 创建的资源和启动的工作应有明确的所有者，以及相应的释放、取消或恢复策略。
- 清理应遵守作用域和依赖关系；同一作用域内的资源按获取顺序逆序释放，清理入口应可安全重复调用。
- 异步工作应有明确的生命周期归属、完成条件和取消策略；释放资源前，先确保使用它的工作已经结束。
- 部分失败和取消后仍应维护状态一致性，并尝试完成其余必要清理。
- 只捕获能够处理的异常，不静默丢弃失败；转换异常时保留原始原因，维护调用方可依赖的错误与取消语义。
- 等待期限、工作取消与资源释放应有独立且明确的语义；诊断应能解释尚未完成的工作及其归属。
- 持续增长的工作与诊断数据应有容量策略，容量耗尽时提供可观察、可处理的行为。
- 区分生命周期推进与业务就绪，启动失败和依赖阻塞应能够被宿主识别。

## SOLID

- **单一职责**：按变化原因划分职责，根据内聚性与复杂度拆分，避免以固定行数决定结构。
- **开闭原则**：在已知变化点提供清晰的扩展边界，避免重复修改核心逻辑，也避免为假设需求提前抽象。
- **里氏替换**：替代实现不仅要满足类型签名，还应遵守行为、状态、异常和生命周期契约。
- **接口隔离**：接口围绕消费者需要组织，避免迫使调用方依赖无关能力。
- **依赖倒置**：策略依赖稳定契约，外部条件与易变实现保持可替换；避免隐式的全局耦合，共享状态应有明确边界。

## Pythonic

- 优先使用语言惯用写法和标准库能力，以可读性决定表达方式。
- 保留框架的行为目标，优先采用 Python 的语言机制与使用习惯；跨语言实现不要求接口形式一致。
- 依赖通过显式接口获取，再以普通参数传递；避免让动态属性、隐式代理或环境状态成为常规业务代码的前提。
- 资源管理优先使用上下文管理器和明确的清理注册；不同生命周期应有清晰入口，避免让返回值承担过多隐含含义。
- 区分值与可变实体，避免意外共享可变状态。
- 使用与作用域相匹配的资源管理和并发机制，避免失去所有权的后台工作。
- 保持控制流直接、命名明确、公开边界清晰；动态行为应有明确契约和测试保护。
- 公开接口的文档说明行为、约束及必要的失败语义；注释解释设计理由和不明显的限制。
- 性能优化应由实际需求或测量结果驱动，避免以牺牲清晰性换取未经验证的收益。

## 提交前

- 按项目约定运行与变更相关的测试、类型检查和静态检查。
- 确认行为契约、生命周期和失败路径得到适当验证，文档与实现一致。
- 说明变更目的、验证结果，以及尚未验证的限制。
