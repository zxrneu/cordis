# Python Cordis 缺陷修复（2026-09-13）

[返回实现参考](implementation.md) · [原始审计](bug-audit-2026-09-10.md)

已修复审计中的 B01–B08、K01–K02 共 10 项缺陷，并补充相关取消、并发、配置恢复和包缓存失败路径。此次修改针对 Python 运行时，不代表所有平台、示例和外部插件已穷尽审查。

## 修复与回归

| 编号 | 修复后行为 |
| --- | --- |
| B01 | 换 Realm 后，旧激活的在途任务与 cleanup 仍可访问提交时的旧依赖；新激活使用新域，新派生 Context 的显式隔离仍受检查 |
| B02 | 初始化失败与 dispose 并发时，已撤销实例清理后进入 DISPOSED，清除 UID 并从运行时移除 |
| B03 | 目标变化中断初始化不再误报 MissingProvisionError；异步配置校验后重新检查目标，依赖恢复后可再次激活 |
| B04 | HMR 同步恢复 sys.modules 与父包属性，并移除失败导入引入的模块与绑定 |
| B05 | HMR 调用者取消时，等待导入、替换或回滚收尾后再传播取消；不会遗弃候选检查与恢复 |
| B06 | 成功销毁的 Fiber 从父 Effect 脱离，父级不再通过 cleanup 闭包保留它；失败清理仍保留用于后续错误报告 |
| B07 | 非法 yield 和初始化错误会关闭未耗尽的同步/异步生成器；关闭也失败时保留两个错误，collector 始终复位 |
| B08 | 在原调用 Task 中检查 Effect 及子 Effect 的自等待关系；受管消费者不能通过服务清理句柄等待自身退出 |
| K01 | Entry 只记录成功应用的配置；更新失败恢复旧 Entry，重复提交同一失败配置会重新尝试 |
| K02 | 候选导入和结构校验先于旧条目删除；应用失败后恢复本轮受影响旧挂载与配置 |

原审计的 11 个用例（含 L01 能力边界）已迁入 [test_regressions.py](../tests/test_regressions.py)，不再使用 expectedFailure。[原复现入口](repros/bug_audit_20260910.py)仍可运行，保留 --strict 兼容参数。

## 同时补齐的失败路径

- Fiber.update 在自等待检查、已销毁检查之后才校验或修改配置；调用取消会等待更新或默认恢复结束。
- 同一 Loader 的 mount、unmount、reconcile、reload、HMR 与 close 共用锁；排队时取消不应用变更，初始化期间递归修改同一 Loader 会明确报错。
- reconcile 保存旧条目与上下文设置，恢复移除项及此前成功更新项；传播组内启动失败和因提供者变化产生的消费者失败。update hook 主动抛出 CancelledError 也会恢复本轮其他条目。
- 并行候选导入即使已有失败也等待全部线程完成，避免返回后仍修改模块缓存。
- 接受包模块时包含已缓存子模块，避免旧子模块被复用；reload_changed 在扩展后检查 externals，不能绕过 external 子模块边界。

扩展测试见 [test_failure_paths.py](../tests/test_failure_paths.py) 和 [test_hmr_failure_paths.py](../tests/test_hmr_failure_paths.py)。

## 调用契约与限制

操作开始后取消调用方，会等待操作提交或恢复，再抛出 CancelledError；**取消不等于撤销已成功提交的变更**。可通过 config、Loader.entries/get 查询结果。等待统一使用 shield 并继续监督结果，重复取消也不会遗弃收尾。

恢复成功仍传播原更新错误；恢复自身失败会聚合报告。恢复不提供数据库式隔离，不会撤销文件写入、网络请求或自定义 hook 的任意外部副作用。不同 Loader 与直接 Fiber 更新不共用全局锁。

L01（外层 HMR 不自动递归 group 子 Loader）、动态 import 图覆盖、通用 cleanup 超时、忽略取消的任务和外部资源仍属能力边界，见 [Loader API](api/loader.md)、[HMR API](api/hmr.md) 和 [维护清单](implementation.md#维护清单)。
